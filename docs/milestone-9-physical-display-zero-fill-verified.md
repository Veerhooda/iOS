## 2. Root Cause Analysis & Fixes Verified

### A. The Opaque-Black Alpha Masking Bug
- **Discovery:** In 32bpp BGRA/ARGB surfaces, an opaque black pixel has value `0xFF000000` (Alpha=0xFF, RGB=0x00). The previous sampling check `if (row[x] != 0)` treated opaque black as valid non-zero content, falsely reporting 5,001 non-zero pixels on `backboardd`'s empty composite targets (Surfaces 3 & 5).
- **Consequence:** `fClientUI` believed the render server had drawn valid content and bypassed client surface redirection, blitting black zeroes into physical panel memory (`fPixels`).
- **Fix:** Changed sampling condition to `if ((row[x] & 0x00FFFFFF) != 0 && ++nz > cap)`. Opaque black is now correctly recognized as empty (`nz == 0`).

### B. Frame Memory Zero-Fill Prevention
- **Fix:** When an incoming composite frame has 0 visible RGB pixels (`shown_nz == 0`) and the panel previously held valid UI content (`sHasNonZeroUI == true`), `AppleCLCD::present` returns immediately without zero-filling `fPixels`.
- **Verdict in Run 183:** Caught and prevented 5 separate zero-fill wipes:
  - `OP2 FB: preserving last non-zero frame (surface 3 has no RGB pixels)` (×3)
  - `OP2 FB: preserving last non-zero frame (surface 5 has no RGB pixels)` (×2)

### C. Client UI Search Space & Overlay Cleanup
- **Search Space:** Expanded `sid` scan from `< 24` to `< 64`, capturing all double-buffered Retina surfaces generated by SpringBoard.
- **Overlay Retirement:** Removed the forced override in `present()` that replaced valid userland Surface 2 with blank buffers.
